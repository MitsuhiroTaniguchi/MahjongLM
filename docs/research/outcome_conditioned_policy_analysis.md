# Outcome‑Conditioned Mahjong Policy: 理論と実装の橋渡し

**対象**: `mitsutani/mahjonglm-10m`（ベース）と `mitsutani/mahjonglm-10m-oc`（最終着順を先頭付加して fine‑tuning した LoRA アダプタ）
**理論的基盤**: Daniel Russo, *Success Conditioning as Policy Improvement: The Optimization Problem Solved by Imitating Success*, arXiv:2601.18175v1 (2026)
**作成**: 2026‑05‑29

---

## 0. TL;DR

- Russo (2026) は **success conditioning（成功軌跡の模倣）= 保守的な方策改善作用素** であることを厳密に証明した。具体的には、success‑conditioned policy `π⁺(a|s) = P_{π₀}(A_t=a | S_t=s, R(τ)=1)` は、χ² ダイバージェンスで測った信頼領域内で一次の方策改善 `L_{π₀}(π)` を**厳密に最大化する解**である（Prop 4.1）。
- 本リポジトリの OC モデルは、`<bos> final_rank_* … <元の view_imperfect 列> <eos>` という形で**ゲーム全体の最終着順ベクトル**を先頭に付加して SFT したものであり、これは Decision Transformer / return‑conditioning 系（論文 §7.1）に正確に対応する。
- 理論の中心的帰結（**Action‑Influence Identity**, Prop 4.4）は、本実装に対し次の検証可能な予測を与える:
  1. 「目線プレイヤー＝トップ」で条件付けた方策 `π⁺` は、ベース `π₀` から **χ² の意味で動いた分だけ、ちょうど真の勝率を改善する**（Corollary 4.5: 改善は常に非負、決して劣化しない）。
  2. その**改善の大きさ＝方策の動きの大きさ＝action‑influence** であり、三者は各状態で**厳密に等しい**。したがって `χ²(π⁺‖π₀)` は訓練時に観測可能な改善の代理指標になる。
  3. 失敗様式は「危険な分布シフト」ではなく「**ほとんど動かない過保守**」として観測可能に現れる。
- **本設定に固有の最大の論点**: 麻雀は**確率的・多人数**ゲームであり、最終着順は自席の意思決定だけでなく山・他家の挙動という制御不能な確率変数に強く依存する。論文の最もクリーンな保証（Prop 5.1 の `M=1`、分布シフト罰則ゼロ）は**決定論的遷移**を前提とし、これは自己回帰の「トークン生成」レベルでは成り立つが、**ゲーム結果**のレベルでは成り立たない。結果として「rank=1 のハード条件付け」は論文 §6 が警告する**閾値が高すぎるレジーム（“counting on luck”）**に該当し、**真の効用と不整合になるリスク**を持つ。
- ユーザが述べた「**着順ごとに効用を定義し、これを最大化する**」という方針は、論文 §6.1 の **faithful binary reduction**（`R ~ Bernoulli(Y(τ))`, `Y` = 着順効用を [0,1] に正規化したもの）に厳密に対応し、上記の不整合を原理的に取り除く**正しい修正**である。本書はこれを中心的な研究方針として推す。
- **実測（§7.5）の要点**: 現 OC チェックポイントを held‑out 2024 で測ると、**着順条件をほぼ使えていない**（「viewer=トップ」条件と「viewer=ラスト」条件で方策が打牌 χ²≈2e‑5・立直 |Δ|≈0.0004 とほぼ同一）。一方で χ² 幾何は守られ（base が稀とした手へ確率を移さない）、危険な分布シフトは起きていない。よって「OC(top) > base」は現状**未実現**だが、これは理論の反証ではなく**条件付けの学習不足**であり、§6 の効用化＋学習量増が次の一手。

## 1. 設定の形式化

### 1.1 MDP としての麻雀シーケンスモデル（論文 §2, Example 2.1）

論文の枠組みでは、状態は「これまでに生成したトークン列」、行動は「次トークン」、遷移は決定的（トークンを追記するだけ）である。本リポジトリの `view_imperfect_{seat}` 列はまさにこの形をとる。

- **状態** `S_t` = `<bos>` から現在位置までのトークン接頭辞（目線 seat の観測可能履歴。他家の手牌・ツモは `hidden_haipai_*` / `draw_*_hidden` にマスクされる — `src/tenhou_tokenizer/views.py`）。
- **行動** `A_t` = 次トークン。ただし**方策として意味を持つ行動**は目線プレイヤーの意思決定トークンに限られる:
  - 打牌: `discard_{seat}_{tile}_{tedashi|tsumogiri}`
  - 自家オプションの take/pass: `take_self_{seat}_{riichi|ankan|kakan|tsumo|kyushukyuhai|penuki}` / `pass_self_…`
  - 反応オプションの take/pass: `take_react_{seat}_{chi|pon|minkan|ron}` / `pass_react_…`
  - その他のトークン（他家の公開打牌、ドラ表示、ツモ・流局・点数）は「環境」に相当するが、シーケンスモデルはこれらも生成するため、論文の枠組みでは**環境の確率性もモデルの行動ドローに畳み込まれている**。
- **報酬** `R(τ) ∈ {0,1}` = 終局時の成功判定。本 OC モデルでは「目線 seat の最終順位（`final_rank_{seat}_{place}`）」を条件として与えることで実現する。

### 1.2 本リポジトリの outcome‑conditioning 構成

`src/gpt2/outcome_conditioning.py::build_outcome_conditioned_input_ids` が生成する系列は次の通り（`docs/outcome_conditioned_unsloth.md`, `tests/test_outcome_conditioning.py` で確認）:

```
<bos> final_rank_0_p₀ final_rank_1_p₁ final_rank_2_p₂ final_rank_3_p₃  <元の view_imperfect_{seat} 列>  <eos>
```

- 四麻なら 4 個、三麻なら 3 個の `final_rank_*` を先頭に置く。各 `final_rank_{seat}_{place}` は席ごとの最終順位で、**全席の着順の完全な置換**を与える（`place` は重複なし）。
- すなわち本モデルは**目線プレイヤーの順位だけでなく全席の最終順位ベクトル全体**で条件付けされている。「目線プレイヤーがトップ」は、`final_rank_{viewer}_1` を固定し、残り 3 席に {2,3,4} を割り当てた完全順位を指定することで表現する。
- ベース `mahjonglm-10m` は Qwen3 系（hidden 256, 13 層, 4 head/1 KV head, vocab 828, ctx 16384, ~10M params, bf16）。OC は LoRA（r=64, α=128, dropout 0, 全 attention+MLP proj 対象）で約 0.11 epoch（checkpoint‑50200, eval loss 1.103）学習。

> **実装上の確認事項（要検証）**: ベース 10m の `training_config.json` の `dataset_dirs` は `huggingface_datasets_omniscient/{year}` を指す。本リポジトリのデータ生成（`huggingface.py::_iter_year_rows`）は 1 ゲームから complete/omniscient/imperfect_0..3 の全 view 行を出力するため、ベースは imperfect view も含めて学習済みと解釈できる。ただし view ごとの混合比が OC fine‑tuning（imperfect のみ）と異なるなら、OC アダプタは「imperfect view への適応」と「outcome conditioning」を**同時に**学習しており、比較時に交絡し得る。§7 の対照実験で切り分ける。

## 2. Russo (2026) の核心（本設定に必要な部分の要約）

記号: `ρ(π)=P_π(R=1)` 成功確率、`V^π(s)=P_π(R=1|S_t=s)`、`Q^π(s,a)`、`A^π(s,a)=Q−V`、占有測度 `d_π`、成功条件付き占有 `d⁺_π`。

1. **success‑conditioned policy（Lemma A.1）**
   `π⁺(a|s) = π₀(a|s)·Q_{π₀}(s,a)/V_{π₀}(s) = π₀(a|s)·(1 + A_{π₀}(s,a)/V_{π₀}(s))`
   → 成功軌跡上の行動分布の模倣＝成功軌跡での next‑token 予測損失の最小化（§2）。**SFT on filtered/conditioned trajectories がこれを近似する。**

2. **action‑influence（Def 3.2）**
   `I_{π₀}(s) = (Std_{a∼π₀}[Q_{π₀}(s,a)] / E_{a∼π₀}[Q_{π₀}(s,a)])²` = 行動ドローが成功確率に与える変動（変動係数の二乗）。`= E_{a∼π₀}[(A_{π₀}(s,a)/V_{π₀}(s))²]`。

3. **Trust‑Region Equivalence（Prop 4.1）**
   `π⁺ = argmax_π L_{π₀}(π)  s.t.  Σ_s d⁺_{π₀}(s) χ²(π(·|s)‖π₀(·|s)) ≤ Σ_s d⁺_{π₀}(s) I_{π₀}(s)`。
   半径は**データから自動決定**（ハイパラ不要）。幾何は χ²（KL ではない）。

4. **Action‑Influence Identity（Prop 4.3 / 4.4）** — 各状態で厳密に等号:
   `A_{π₀}(s,π⁺)/V_{π₀}(s) = χ²(π⁺(·|s)‖π₀(·|s)) = I_{π₀}(s)`。
   集計版: `L_{π₀}(π⁺)/ρ(π₀) = Σ d⁺ χ²(π⁺‖π₀) = Σ d⁺ I_{π₀}`。

5. **単調改善（Corollary 4.5）**
   `ρ(π⁺) ≥ ρ(π₀)` かつ `(V^{π⁺}(s)−V^{π₀}(s))/V^{π₀}(s) ≥ I_{π₀}(s) ≥ 0`。
   **決して劣化しない。** 失敗は「動かない（I が小さい）」過保守として現れる。

6. **χ² vs KL の幾何（§4.5, Lemma 4.6, Fig 1）**
   χ² 制約は「**π₀ で稀だった行動へ確率を移すこと**」を重く罰し（rare action の上限は `Θ(√δ)`）、一方で「**π₀ で十分支持された行動への集中**」は許す。TRPO の reverse‑KL（“忘却が高価”）とは逆の偏り（“**探索が高価**”）。→ success conditioning は**保守的・支持内集中型**。

7. **データからの学習（Prop 5.1）**
   `|ρ(π̂)−ρ(π⁺)| ≤ √(M·Δ/2)`, `Δ` = 過剰交差エントロピー, `M = sup_s d⁺_{π₀}(s)/d_{π⁺}(s)`。
   **決定論的遷移（自己回帰生成を含む）では `M=1`** → 分布シフト罰則ゼロ、オフライン損失が素直に展開性能に転写。

8. **密報酬・return thresholding（§6）**
   `Y(τ)∈[0,1]` に対し `R ~ Bernoulli(Y)` とすれば `E[R]=E[Y]` で**真の目的を保存**（faithful reduction, §6.1）。
   一方 `R̃=1{Y>θ}`（return thresholding）は **proxy reward**。Prop 6.1:
   `A_{π₀}(s,π̃⁺)/A_{π₀}(s,π⁺) = √(Ĩ/I) · Corr(A, Ã)`。
   → proxy は変動係数（識別力）を上げれば改善を増幅し得るが、**alignment（真報酬との相関）を失えば改善は負に転じる**。閾値が高すぎると「分散の大きい（=運の要素が強い）行動」を選好し、平均性能を悪化させる（“counting on luck”）。

## 3. 本実装への対応付け（厳密に）

| 論文の対象 | 本実装での対応 |
|---|---|
| 行動方策 `π₀` | ベース `mahjonglm-10m` の次トークン分布（天鳳ログ＝強豪人間の模倣分布） |
| success‑conditioned policy `π⁺` | OC モデルを「全席着順ベクトル（viewer=1位）」で条件付けた次トークン分布 |
| 成功事象 `R(τ)=1` | 目線 seat の最終順位が指定値（例: 1位）であること |
| 状態 `S_t` | `view_imperfect_{seat}` のトークン接頭辞 |
| 行動 `A_t` | 次の意思決定トークン（打牌/立直/鳴き/ロン の take‑pass 等） |
| 決定的遷移 | **トークン追記**としては成立（Prop 5.1 の前提を局所的には満たす） |

**重要な微妙点**: 論文の `π⁺` は「**同じ** π₀ の下での成功条件付き分布」を Bayes で定義する。本 OC モデルはそれを LoRA‑SFT で**近似**したもの。Prop 5.1 はこの近似誤差 `Δ` を展開性能に結びつけるが、**`M=1` が言えるのはトークン遷移が決定的な範囲**に限られる。麻雀の「最終着順」は接頭辞から決定的に定まらない（将来の山・他家依存）ため、状態を「目線の観測履歴」にとると `R` は状態の決定的関数ではなく、**`M>1`（分布シフト罰則が残る）**。これが §5 の理論的クリーンさが本設定では完全には享受できない理由であり、§6 の proxy/luck 分析が前面に出てくる理由でもある（→ §5 で詳述）。

## 4. 「目線プレイヤー＝トップなら強い」主張の理論的評価

ユーザの期待:
> oc モデルでこの目線プレイヤーがトップだったと conditioned した場合の選択は、ベースモデルで non‑conditioned に推論した選択より強い分布を示す。

**理論が保証すること（成り立つ部分）**:
- もし OC が `π⁺`（=faithful な成功条件付き分布）を良く近似しているなら、Corollary 4.5 により **`π⁺` は `π₀` より真の成功確率を弱改善する**（`I_{π₀}(s)≥0` の分だけ）。**劣化は理論上起きない。**
- 改善の大きさは action‑influence `I_{π₀}(s)` に等しい。麻雀の各局面で「人間の行動選択のばらつきが最終順位にどれだけ効くか」が大きい局面ほど、条件付けの効果が大きい。

**理論が警告すること（成り立たない／危険な部分）**:
- 「**トップ（1位）に固定**」は `R̃ = 1{place=1}`、四麻なら上位 25% の閾値条件付けに相当し、§6 の **return thresholding（高すぎる θ）** と同型。
- 麻雀では順位は**運（配牌・ツモ・他家の放銃）に強く依存**するため、「1位で終わった軌跡」には「**強い意思決定**で勝った軌跡」と「**運良く勝った**軌跡」が混在する。Prop 6.1 の `Corr(A, Ã)`（真の効用と proxy の整合）が低下する局面では、OC(top) は「分散が大きく運任せな手（高め狙いの危険な押し等）」を選好し得る。これは Paster (2022) / Yang (2023) の “you can't count on luck” の麻雀版である。
- さらに本モデルは**全席着順ベクトル**で条件付ける。「viewer=1位 かつ 他家の順位も特定」という指定は、特定の決着パターン（例: 親の連荘で2着が誰、等）を含意し、条件付け分布がデータ希薄な組合せに当たると `π⁺` の推定が不安定になり得る。

**結論**: 「OC(top) > base」は**平均効用で見れば概ね期待できる**（χ² 幾何の保守性ゆえ大崩れしにくい）が、**1位ハード条件付けのままでは “運に賭ける” バイアスにより一部局面で真の強さと乖離**する。ユーザの「着順効用を定義して最大化」方針こそが、この乖離を消す**理論的に正しい設計**である（§6）。

## 5. 確率的・多人数性がもたらす理論的ギャップ

論文の枠組みは「単一方策 π₀ が全軌跡を生成」する MDP を仮定する（Remark 2.2 で履歴を状態に含めれば mixture でも可）。麻雀へ適用する際の三つのギャップ:

1. **遷移の確率性（山・ツモ）**: トークン生成は決定的でも、`R`=着順は目線の観測接頭辞から決定的でない。→ `M>1`、Prop 5.1 の罰則ゼロは不成立。
2. **多人数性（他家も学習方策）**: π₀ は「自席＋他家全員が天鳳人間分布」を表す。OC(top) で自席を改善しても、**他家が固定された人間分布のまま**という仮定の下での改善であり、自己対戦で全席を OC 化したときの均衡は別問題（iterated success conditioning, 論文 §8 の open problem）。
3. **長期信用割当**: `final_rank` は半荘終局時の唯一のシグナル。1 半荘の意思決定数は数百に及ぶため、action‑influence は長期化し、個々の打牌の寄与は希薄（→ 過保守側に倒れやすい）。論文 §8 が示唆する **action chunking**（複数手をまとめて条件付け）や局単位の中間報酬の導入が効く可能性。

これらは「OC が効かない」という意味ではなく、「**効果は局面の action‑influence に比例し、かつ luck‑misalignment で目減りし得る**」という定量的予測である。

## 6. 推奨する中心方針: 着順効用による faithful reduction

ユーザの直観を論文 §6.1 に接続して定式化する。

- 着順効用 `u(place)` を定義（例: 天鳳の順位ウマ、`u(1)=+90, u(2)=+45, u(3)=0, u(4)=−135`、あるいは MMR 期待値）。
- 半荘の正規化リターン `Y(τ) = (u(place_viewer) − u_min)/(u_max − u_min) ∈ [0,1]`。
- **faithful 成功ラベル** `R ~ Bernoulli(Y(τ))`: 各軌跡を確率 `Y` で「成功」と確率的にラベル付け。`E[R]=E[Y]` ゆえ **success conditioning は期待効用 `E[Y]` を直接改善する**（§6.1, 罰則・閾値選択不要）。

実装オプション（軽い順）:
- **(A) 重み付き条件付け SFT**: 既存の「全席着順プレフィックス」を維持しつつ、各サンプルの損失重みを `Y(τ)`（または `Bernoulli(Y)` のサンプリング採否）にする。ハード rank=1 フィルタを置き換える最小変更。
- **(B) 効用バケット条件付け**: `final_rank_*` の代わりに（あるいは加えて）`outcome_utility_{bucket}` トークンを先頭に付加し、推論時に最上位バケットで条件付け。Decision‑Transformer の return‑to‑go に対応。
- **(C) 局単位の中間アウトカム**: 半荘着順に加え、各局の得失点符号など中間報酬を条件トークン化し action‑influence を増幅（§5‑3, §8 の action chunking 的発想）。

(A) が論文の faithful reduction に最も忠実で、かつ既存パイプライン（`outcome_conditioning.py`）への変更が最小。

## 7. 検証可能な予測と実験プログラム

理論は「観測可能な診断量」を与える。以下は本リポジトリの 2 モデルで**今すぐ測れる**。

### 予測 P1 — 方策の動き＝改善の代理（Prop 4.4）
held‑out の各 viewer 決定点で `χ²(π_OC(top)(·|s) ‖ π_base(·|s))`（合法行動集合に制限・再正規化）を測る。
- これが**ほぼ 0** の局面 → OC は過保守（action‑influence 小）。効果は期待薄。
- 正で大きい局面 → 改善ポテンシャル大。χ² の集計値は「平均改善の代理」。

### 予測 P2 — χ² 幾何（Lemma 4.6, Fig 1）
`π_OC(top)(a)` を `π_base(a)` に対して散布。理論予測:
- `π_base` で**稀**な行動 `a`（小さい `π_base(a)`）へ大きな確率を移さない（rare‑action 上限 `Θ(√δ)`）。
- `π_base` で**支持された**行動へは集中可（mass concentration 許容）。
- もし OC が稀手へ大きく確率を割く例が頻発するなら、それは χ² 幾何からの逸脱＝(LoRA 近似誤差 or luck‑misalignment) の兆候。

### 予測 P3 — outcome 感応性（過保守の検査）
同一接頭辞で `π_OC(top)`（viewer=1位）と `π_OC(bottom)`（viewer=4位）を比較。
- 両者が**ほぼ同一**なら OC は条件をほぼ無視（学習不足 or action‑influence 極小）。
- 系統的に差が出るなら OC は条件を使えている。差の向きが「1位条件で攻撃的/効率的、4位条件で別様」かを定性確認。

### 予測 P4 — 方向性（成功軌跡の模倣）
held‑out を「viewer が実際に 1位/4位で終局」で層別。viewer が**1位だった**軌跡の実際の着手 `a*` に対し:
- `π_OC(top)(a*|s) > π_base(a*|s)` が平均的に成り立つか（成功手の尤度上昇）。
- 逆に 4位軌跡の実着手に対しては `π_OC(top)` が尤度を下げるか。
これは「success conditioning が成功軌跡を模倣する」核心主張の直接検証。

### 予測 P5 — luck‑misalignment（§6 の核心リスク, 要 simulator）
self‑play 環境で OC(top) を 1 席に投入し他 3 席をベースにして半荘を多数試行、`E[u(place)]` と勝率分布を測る。faithful‑utility 版（§6 の (A)）と rank=1 ハード版を比較し、後者が「分散大・平均同等以下（counting on luck）」を示すかを検証。
※ 本リポジトリには `pymahjong` ベースのエンジン（`src/tenhou_tokenizer/engine.py`）があり、合法手判定・和了判定が利用できる。完全な self‑play ループは追加実装が必要（§9）。

### 実験の段階
1. **静的測定（simulator 不要, 即実行可能）**: P1–P4。本書付属の `scripts/research/measure_policy_movement.py` で実施。
2. **utility‑faithful 学習（中規模）**: §6(A) の重み付き条件付け SFT を追試し、P1–P4 を rank=1 版と比較。
3. **self‑play 強度評価（大規模）**: P5。エンジンを生成ループに接続し着順 EV を測定。

## 7.5. 実測結果（本リポジトリの 2 モデル, held‑out 2024）

予測 P1–P4 を `scripts/research/measure_policy_movement.py`（打牌決定 700 点 / 50 半荘）と `scripts/research/measure_riichi_sensitivity.py`（立直 take/pass 949 点 / 250 半荘）で測定した。`view_imperfect` の held‑out 2024 ゲームを使用。`π_base` は条件なし生入力、`π_OC(top/bot/true)` は `<bos> final_rank…` を前置した入力（他席順位は整合する全順列で周辺化）。

**打牌決定点（合法打牌集合に制限・再正規化）:**

|---|---|---|
| `base_mass_on_discards` | 0.99998 | 決定点検出は正確（次トークン質量がほぼ全て自席打牌に集中） |
| `χ²(π_OC(top) ‖ π_base)` 平均 / 中央値 | 0.067 / 0.025 | 方策は**小さく**動く（TV≈0.063）。プレフィックス前置による微小シフト |

| `max π_OC(top)(a)` on base‑rare (<1%) | 0.0046 | **χ² 幾何を遵守**：base が稀とした手へ確率を移さない（P2 ✓, Lemma 4.6） |

| 指標 | 値 |
|---|---|
| `P(take riichi)`: base / OC(top) / OC(bot) | 0.337 / 0.338 / 0.339 |
| `|P_top − P_bot|` 平均 / 最大 | 0.0004 / 0.010 |
| `|P_top − P_base|` 平均 | 0.0028 |

**結論（実測）**:
1. **本 OC チェックポイントは着順条件をほぼ使っていない。** top と bottom の条件付けで方策がほぼ完全に一致する（打牌 χ²≈2e‑5、立直 |Δ|≈0.0004）。これは Russo の予測する失敗様式「**方策をほとんど動かさないことで観測可能に失敗する**」（Prop 4.3 の解釈）の最も極端な形である。
2. ただし**方策が動かない原因は二つに分離できる**。本実験は両者を区別する: (i)真の action‑influence がゼロ、(ii)条件信号の未学習。**立直**は局面により最適行動が大きく変わる高 influence 決定であり、ここでも無反応ということは (ii)**学習不足/長距離条件信号の未ルーティング**が主因と判断できる（LoRA・0.11 epoch・条件が系列先頭で決定点から数百トークン手前）。
3. **観測された微小な動きは条件の「内容」ではなく「存在」由来**（χ²(top‖base)=0.067 ≫ χ²(top‖bot)=2e‑5）。モデルは「プレフィックスがある」ことは学んだが「その値で条件付ける」ことを学べていない。
4. **χ² 幾何は守られている**（base‑rare な手へ確率を移さない）。すなわち「危険な分布シフトで失敗」はしておらず、論文の保守性は実測でも確認できる。
5. したがってユーザの期待「OC(top) はベースより強い分布」は**現チェックポイントではまだ実現していない** — 理論の否定ではなく、**条件付けの学習が不足**しているため。§6 の utility‑faithful 化と学習量増（§9‑4）が次の一手。

> 再現: `PYTHONPATH=src python scripts/research/measure_policy_movement.py --num-games 50` および `scripts/research/measure_riichi_sensitivity.py --num-games 250`（要 HF 認証, ベースは gated）。

## 7.8. v2 再設計（OCモデルの作り直し）

§7.5 の診断（着順条件の未学習・系列先頭の信号が決定点に届かない）に基づき、OCモデルを次の三点で作り直す。実装は `src/gpt2/outcome_conditioning.py::build_outcome_conditioned_v2` と `scripts/train_outcome_conditioned.py`。

## 7.9. v2 学習済みモデルの解剖（checkpoint-44000）

v2（full FT・`reinject=turn`・`loss_scope=actions`）を 2022–2024 で約 0.65 epoch 学習（`outputs/mahjonglm-10m-oc-v2/checkpoint-44000`、eval action-loss ≈ 0.467 で収束）。**学習対象外の 2021** で解剖（`scripts/research/dissect_oc_v2.py`, `dissect_riichi_v2.py`）。

**測定結果（held-out 2021, 打牌1280点 / 80半荘, 立直1932点 / 400半荘）:**

| 指標 | checkpoint-44000 | 0.2ep smoke(action) | v1 |
|---|---|---|---|
| TV(π_top ‖ π_bot) 打牌 | **0.0076** | 0.019 | 0.0008 |
| TV(π_top ‖ π_base) | 0.037 | — | — |
| 勝者の実着手 p: top / bot | 0.6712 / **0.6717** | — | — |
| 敗者の実着手 p: top / bot | 0.6913 / 0.6919 | — | — |
| 立直 P(take): top / bot | 0.372 / 0.374 | — | — |
| 立直 平均 |Δ| / 最大 |Δ| | 0.009 / **0.170** | — | — |
| 立直 |Δ|>0.05 の割合 | **2%** | — | — |
| base-rare 手への最大確率(π_top) | 0.003 | — | — |
| 局面別 TV(top,bot) early/mid/late | 0.007/0.008/0.008 | — | — |

**核心の発見:**

1. **収束した v2 モデルは、打牌・立直のほぼ全てで着順条件にほぼ無感応**（打牌 TV≈0.0076、立直 平均|Δ|≈0.009）。しかも**学習が進むほど感応性は下がった**（0.2ep の 0.019 → 0.65ep の 0.0076）。
2. **決定的証拠（バグ・学習不足ではない）**: *真の*着順で条件付けても *偽の*着順で条件付けても、その局の実着手の尤度が改善しない（勝者 top=0.6712 ≤ bot=0.6717）。もしモデルが条件を意味的に使えていれば、真の着順条件で実着手尤度が上がるはず。上がらない＝**観測状態を所与とすると、打牌は最終着順とほぼ条件付き独立**。再注入も action-loss も投入済みなので、§7.5 で疑った「学習不足／配線」ではない。
3. **理論的帰結（Russo 2026）**: これは action-influence `I(s) ≈ 0` の状態であり、`π⁺(a|s) = π₀(a|s)(1 + A/V)` より **π⁺ ≈ π₀**（過保守失敗様式, Prop 4.3/Cor 4.5）。**最終着順は個々の打牌に対して遠位かつ運に支配されすぎており**、一手と着順の（状態を条件とした）相互情報が小さい。
4. **ただし action-influence はゼロ一様ではなく“局在”する**: 立直判断の **約2% に |Δ|>0.05（最大 0.17）** の実質的な方策移動。これはオーラス等、**現在の選択が着順を実際に左右する高レバレッジ局面**に対応する。OC はそこだけで方策を動かし他では behavior policy に留まる——まさに保守的改善作用素の挙動。
5. **χ² 幾何は厳守**: π_top が base 稀手へ移す確率は最大 0.3%。危険な分布シフトは皆無。

**結論**: 「最終着順の outcome conditioning だけでは、麻雀の per-move 方策をほとんど強化できない」。理由は学習側ではなく**条件変数の選択**——終局着順は遠位・高分散で action-influence が小さい。改善は理論が予言する高レバレッジ局面に正しく集中するが、全体効果は小さい。

**処方（次の設計）**: action-influence を上げる条件変数に変える。
- **近位・密なアウトカム条件**: 局単位の得点差分 / 和了・放銃・聴牌などの中間結果トークンを（終局着順に加えて／代えて）条件化。個々の決定と強く結合し `I(s)` を大きくする。
- **action chunking**（Russo §8）: 局内の複数手をまとめた単位で条件付け。
- **placement-pressure 特徴**: OC が既に効いているオーラス近傍の着順圧力を明示特徴化して増幅。
- 終局着順の効用化（§6）は alignment を整えるが、**遠位性の問題は残る**ため、局レベル信号の方が大きなレバー。

## 7.9.1 実装ミスの検証（無感応は artifact ではない）

「無感応」が前処理/測定バグの artifact である可能性を潰すコードレビューを実施。

- **席フレーム（qijia）バグ仮説 — 反証済み**: ボディは round-relative/qijia-relative、`final_rank_{seat}` は game-absolute フレームで、ビルダーが `final_rank_{viewer_seat}` を「目線の着順」として抽出するのは qijia≠0 で誤席を指すのでは、と疑った。**合成ゲーム（qijia=2、各席に一意の字牌マーカー）で実証した結果、`view_imperfect_{p}` が公開する手牌は絶対ログ席 `p` であり、`final_rank_{p}` と一致**。qijia オフセットは `_viewer_round_seat` と `_current_game_order_scores` で相殺され全フレームが「ログ順」で一貫。バグなし。
- **決定的な情報量テスト**（`scripts/research/verify_conditioning_information.py`, held-out 2021, 150半荘）: 行動トークン NLL を「真の着順条件」vs「誤った着順条件（目線の順位を入替）」で比較。

  | 条件 | action NLL |
  |---|---|
  | 真の着順 | 0.47226 |
  | 誤った着順 | 0.47570 |
  | 低減 | 0.0034 nats（相対0.7%）、per-game で true が良い割合 = **0.50（偶然）** |

  → 終局着順は状態を所与とすると目線の一手について **≈0.003 nats/手 しか情報を持たない**（per-game では半々＝系統的利得なし）。これは「genuine low action-influence」の直接測定。**かつ微小に正＋オーラス2%テール**は、モデルが条件を正しく配線して読めている証拠（フレームバグ/無視なら 0 かランダム）。
- **その他の確認（クリーン）**: 再注入位置（自摸の2–5手前＝長距離ルーティングの言い訳なし、それでも平坦）、loss マスク/行動トークン分類（リーク・forced_priority 混入なし）、probe の位置整合（top_c/bot_c は構造同一・順序zip）、top_c/bot_c がローカル再注入トークンで実際に異なること。

**総合判定**: 無感応を人為的に生む実装ミスは発見されず。最有力だった席フレーム仮説は反証。3つの独立検証（合成フレーム一致・情報量≈0.003 nats・オーラステール）が「終局着順条件の per-move action-influence は本質的に小さい」を支持する。残る非バグの設計上の制約は「終局着順が遠位すぎる」点で、処方（局レベルの近位アウトカム条件化）は §7.9 の通り。

## 7.10 v3（近位アウトカム条件付け）完全実装と結論

§7.9 の処方「終局着順は遠位すぎる→近位アウトカムで action-influence を上げる」を完全実装した。

**実装（すべて検証済み）**:
- `src/gpt2/round_outcome.py`: 局単位の目線プレイヤー符号付き点差を TENBO デコードで復元し 5 バケット化（bigwin/win/zero/loss/bigloss）。保存則（局収支合計＝最終点−開始点）を held-out 1000局で **1000/0** 検証（サンマ35000開始も考慮）。席は `kyoku_{k}` から `(viewer−k)%n` で確定（2811局で draw 席と完全一致）。
- `build_outcome_conditioned_v3`（`outcome_conditioning.py`）: 終局着順プレフィックス＋**各自摸直前に当該局のバケットを再注入**（turn）＋行動点限定 loss。`override_bucket`/`round_buckets` で反実仮想条件付け可。
- `train_outcome_conditioned.py --scheme v3`: 新規5トークンを語彙追加＋埋め込みリサイズ＋**既存平均で warm-init**（コールドスタート回避）。
- 検証: `scripts/research/verify_v3.py`（情報量 NLL: 真バケット vs 局シャッフル、感応性: bigwin vs bigloss）。

**モデル非依存のデータ分析（信号は存在する）**: 局バケット別の行動率 P(立直)=bigwin 0.589 / win 0.310 / zero 0.059 / loss 0.142 / bigloss 0.298（range 0.53）。局結果は行動を**強く**予測する。

**学習済み v3 の測定（held-out 2021, warm-init, 1.36 epoch）**:

| 指標 | v3 (1.36ep) | v2 (0.65ep) |
|---|---|---|
| 情報量: 真 vs シャッフル NLL 低減 | **−6e‑5**（per-game true優位 0.43＜偶然）| 真 vs 偽 +0.0034 |
| 打牌 TV(bigwin‖bigloss) | 0.0021 | 0.0076 |
| 立直 P(take) bigwin / bigloss | 0.3735 / 0.3734（\|Δ\|≈0.0017）| 0.372 / 0.374 |

**結論（重要）**: 近位の局アウトカムでも、条件付けは**ほぼ無視される**。データには強い相関（P(立直\|bucket) 0.06→0.59）があるのに、学習済みモデルでは条件付き感応性が≈0。これは矛盾ではなく **交絡** で説明される:

> **専門家の行動 ⊥ アウトカム ∣ 観測状態**（終局・局の両horizonで近似的に成立）。

P(立直∣bucket) の大変動は、**状態（聴牌の良さ・手の価値）が立直とその局の好結果の両方を生む**ことによる見かけの相関であり、状態を所与とした残差（モデルが条件トークンから引き出せる情報）は小さい。モデルは状態から行動をほぼ決定でき、条件トークンは限界予測価値を持たないため**勾配が条件利用に流れず無視**される。これは Decision Transformer 系が**行動品質の多様なデータ**で機能するのと対照的——天鳳の**専門家一様データ**では action-influence が構造的に小さい。

**Russo 理論との整合（最終形）**: success conditioning の改善量 = behavior policy の action-influence。**専門家を模倣する限り action-influence は小さく、条件付けの horizon を縮めても（v3）解決しない**。改善を得るには behavior policy 側の action 多様性（＝結果に効く選択のばらつき）が必要。

**したがって真に有効な次の方向**（horizon ではなく behavior 多様性を変える）:
1. **混合棋力データでの OC**: 低段位を含むデータで学習すると action∣state がアウトカムと相関し、「勝者条件付け」が混合 behavior を上回る真の改善になり得る（RvS/DT が要求する前提を満たす）。
2. **明示的最適化**: 条件付け（imitation）でなく value/advantage 推定や DPO（既存 `view_imperfect_dpo`）で behavior を超える。
3. **action-influence の直接推定**で改善の上限を定量化。

## 7.11 直交化分析 ——「直交成分を除き改善成分を取り出す」

アウトカム O を 状態成分 V(s)（直交＝交絡）＋ 行動成分 A(s,a)（改善）＋ 運 に分解し、状態成分を除いて改善成分を取り出す（Russo §7.2 の AWR と同型）。実装 `scripts/research/residual_action_influence.py`：モデル隠れ状態（局頭の自摸位置）へのリッジ回帰で V̂(s) を推定し、残差 = 局収支 − V̂(s) が行動（立直/鳴き/和了）と相関するか測定。

**結果（held-out 2021, 4384局）**:

| 指標 | 値 |
|---|---|
| V̂(状態) の R²（局収支の説明率, test） | **0.015** |
| 局収支 std / 残差 std | 5212 / 5035 |
| 生ギャップ: 立直−非立直 / 和了−非 / 鳴き−非 | +3548 / +9080 / −66 |
| **残差ギャップ（状態除去後）**: 立直 / 和了 / 鳴き | **+3097 / +8376 / −152** |

**二つの発見**:
1. **局結果は局頭状態でほぼ説明できない（R²=1.5%）** — 局中の引き・他家に支配される（運優位）。条件付け信号の大半はノイズ。
2. **A→O の行動影響は実在**（立直は残差+3097点）。だが §7.10 の通り **O→A（条件付け）は無情報**。

**矛盾の解消＝最終結論**: 行動→結果の影響（立直の+3100）は実在するが、**専門家方策に既に織り込み済み**。専門家は良状態で立直・悪状態で降りるため、advantage は behavior 内で使い尽くされ、success-conditioning による再模倣では π⁺≈π₀。直交化は「改善成分」を可視化するが、その成分は (a) 運（exploit 不能）か (b) **既に専門家が exploit 済み**（headroom なし）のいずれかで、**専門家データからの outcome-conditioning では原理的に方策を強化できない**。

> 注意: V̂ は局頭状態ベース（R²が低い＝状態表現が弱い/単一トークン）。立直決定時の聴牌状態で残差化すればより精密だが、**専門家は聴牌でほぼ常に立直する＝行動の反実対照がデータに無い**ため、advantage を綺麗に推定できない。この「対照の欠如」自体が結論を裏づける。

**したがって、改善成分を真に取り出す道は behavior 多様性の導入**:
- **混合棋力データ**: 弱い打ち手は良状態でも降りる/悪状態でも押す等の誤りがあり、action∣state が結果と相関 → success-conditioning が「成功時の行動」を選別して真の改善になる（RvS/DT の前提）。
- **明示的 advantage 推定**（value 関数）で専門家超えの行動を同定 → AWR/DPO/policy-gradient。
- **同一seed反実仮想ロールアウト**（既存 `view_imperfect_dpo`）: 同一状態・同一山から行動だけ変え、結果差＝純粋な action 寄与（状態＋運のベースラインを相殺）。これが「直交成分除去」の最もクリーンな実装。

## 7.12 打牌中心の再分析と不完全情報の本質（最重要）

立直 take/pass は聴牌すれば自明で技量を語らない。麻雀の強さ・プレイヤー差・結果への影響は**打牌**、とりわけ**他家立直下の押し引き＝放銃回避**に表れる。ここに分析を絞り直した（`scripts/research/dissect_discard_pushfold.py`）。

**打牌が結果を支配する（held-out 2021, 7160局, モデル非依存）**:

| 局結果 | 頻度 | 平均点差 |
|---|---|---|
| 放銃 (deal-in) | 13.0% | **−6042** |
| 和了 | 22.7% | +6831 |
| その他 | 64.3% | −1200 |

放銃は高頻度・破滅的損失で、これを避ける打牌が強さの核心。

**だが outcome-conditioning は押し引き打牌でも動かない（v3-smoke3000）**:

| 打牌文脈 | n | TV(bigwin‖bigloss) | NLL低減(真vsシャッフル) |
|---|---|---|---|
| 他家立直下（押し引き） | 5610 | 0.00268 | 7e‑5 |
| 自由 | 24864 | 0.0019 | −5e‑5 |

押し引きは自由打牌の約1.4倍と方向性は正しいが、絶対値はなお極小。

**不完全情報ゲームに固有の決定的理由**:
> 打牌の結果（放銃するか）は、**打牌時に見えない他家の手牌（隠れ情報）に媒介**される。終局/局結果での条件付けは、**決定時に player が持っていなかった隠れ情報を漏らす**が、模倣対象の人間の打牌はその情報なしに打たれている。ゆえに **P(打牌∣不完全情報状態, 結果) ≈ P(打牌∣不完全情報状態)**——結果は「打牌が使えなかった情報」を明かすだけで、deployable な方策改善にならない。

これは §7.5–7.11 の「専門家の advantage は使い尽くされている」に、不完全情報の層を加えた最終形:
1. 専門家の打牌は不完全情報状態を所与にほぼ最適（行動 ⊥ 結果 ∣ 状態）。
2. 残る結果の変動（放銃13%/−6042 等）は、player の情報集合からは**不可約な不確実性（≒運）**——隠れ手牌に依存。
3. 終局でも局でも、結果での条件付けはこの隠れ情報を漏らすだけで、deployment 時に使えない。

**したがって打牌を強化する正しい道**（条件付けではない）:
- **不完全情報下の EV/価値推定**: Q(s_imperfect, tile) を隠れ状態について周辺化して推定し、最大 EV 牌を選ぶ（放銃率予測＝Suphx 系）。条件付けと違い、deployment 時に使える情報だけで最適化する。
- **omniscient→imperfect 蒸留**: 本リポジトリは**全情報の omniscient view**を持つ。omniscient で価値/放銃を学習し imperfect に蒸留すれば、隠れ情報の効果を「教師」として注入できる（条件付けが漏らす情報を、正しく汎化可能な形で渡す）。
- **同一seed反実仮想**（`view_imperfect_dpo`）: 同一局・同一山で打牌だけ変え、結果差＝純粋な打牌寄与（状態＋運を相殺）。

## 7.13 Outcome Ratio Head ——「最適化アーティファクト vs 真の独立」の決着

「conditioning が効かないのは、目的が action-influence を取り出せていない（最適化）だけで、真の信号は存在するのでは」を厳密に検証。標準 conditional LM は `p(a|h,y)` 全体を学ぶため、`a≈f(h)` だと容量の大半を `π0` 再現に費やし残差 `log(π_y/π0)` が埋もれる。そこで **π0 を凍結し残差 `r_y(h,a)=log π_y/π0 = log p(y|h,a)/p(y|h)` だけを学ぶ**（密度比推定）。

実装 `src/gpt2/ratio_head.py`相当 = `scripts/research/extract_ratio_features.py`（frozen base から hidden・logπ0・a⁺・bucket を打牌点で抽出, 323,797点/3000局）＋ `scripts/train_ratio_head.py`（`π_y=softmax(logπ0+r)` 下の a⁺ の CE。離散小行動集合では user の conditional-NCE の K→∞ 厳密版で、最適解は `r=log(π_y/π0)`）。診断は **held-out(by-game) の CE(π_y) vs CE(π0)**、**χ²_y(h)=E_{a~π0}[(e^r−1)²]**、**シャッフルラベル対照**。

| 設定 | real dCE | shuffled dCE | real χ² | shuffled χ² | real TV(top/bot) |
|---|---|---|---|---|---|
| 無正則 (d=256) | −0.011 | −0.010 | 0.69 | 0.21 | 0.099 |
| 正則 (d=64, wd1e‑2) | −0.0003 | −0.0002 | 0.026 | 0.023 | 0.028 |
| 強正則 (d=16, wd3e‑2) | −9e‑5 | **+1e‑4** | 0.016 | 0.015 | 0.025 |

**結論**:
1. **「条件無視」は回避できた**（π0凍結＋残差で TV=0.099 と大きく動く ≫ v2/v3 の 0.002–0.008）。user の診断は正確。
2. **だが汎化する outcome→打牌 信号は ≈0**：held-out CE は π0 を上回らず（dCE≤0）、real と **shuffled ラベル対照が統計的に区別不能**。残る χ²/TV はラベル非依存＝過学習ノイズ。
3. ゆえに失敗は**最適化アーティファクトではなく `A ⊥ Y | H` が真**。専門家打牌の action-influence は本当に小さい——user が提案した**正しい検証法**で確定。

**なぜ真にゼロか（不完全情報の本質, 最終形）**: `r_y(h,a)=log p(y|h,a)/p(y|h)`。打牌の結果への影響は**他家の隠れ手牌**を経由するが、それは imperfect な観測履歴 `h` に含まれない。よって `p(y|h,a)≈p(y|h)` → `r_y≈0`。**情報集合に無い変数を経由する効果は、密度比でも取り出せない。**

**決定的 capstone（実施予定）**: 同じ Ratio Head を **omniscient view**（全手牌＋山が `h` に入る）で学習。隠れ手牌が `h` にあれば打牌の放銃/和了効果が観測可能 → `r_y≫0`（dCE≫0, real≫shuffled）が予測される。これが出れば「**天井は action-influence の欠如ではなく不完全情報**」が証明され、**omniscient→imperfect 蒸留**（見える側で価値を学び見えない側へ転写）が正当な改善路だと確定する。

## 7.14 Capstone: 放銃予測ギャップ（omniscient vs imperfect）と全研究の統合

§7.13 の Ratio Head（条件付け方向）は omniscient だと `p(y|h)` 決定性で交絡するため、**forward 方向**＝「打牌の結果（放銃）が隠れ情報を見れば顕在化するか」を直接測定（`scripts/research/dealin_information_gap.py`）。各打牌を「即ロンされたか」でラベルし、frozen base の隠れ表現から放銃を予測する probe の AUC を view 間比較。

| view | 放銃予測 AUC | 放銃率(per-discard) | n(test) |
|---|---|---|---|
| omniscient（全手牌＋山が `h`）| **0.9997** | 1.2% | 45,052 |
| imperfect（自席視界のみ）| **0.9322** | 1.1% | 34,457 |
| **ギャップ** | **0.068** | | |

**読み**:
1. **omniscient 0.9997**: 他家手牌が見えれば放銃はほぼ決定論的に予測可能 → **打牌の結果への action-influence は実在し大きい**（打牌が核心という直観は正しい）。
2. **imperfect 0.9322（驚くほど高い）**: 公開情報（捨て牌・立直・ドラ・スジ・現物）だけで base は放銃リスクを高精度推定済み → **専門家の安全打牌スキルは既に方策に内在**。
3. **ギャップ 0.068**: 隠れ情報が公開情報の天井を超えて足す分は僅少。かつ難しい高価値ケース（ダマ・隠れ聴牌）に集中。

**全研究（§7.5–7.14）の統合結論**:
専門家データの outcome-conditioning が方策を動かさないのは、独立に確認された3層の理由による:
1. **a ≈ f(h)**（行動は状態でほぼ決まる）→ 標準 conditional LM の CE 最適解は条件を無視（§7.10）。
2. **密度比 r_y も汎化信号 ≈0**（Ratio Head＋シャッフル対照, §7.13）→ 最適化アーティファクトではなく `A⊥Y|H` が真。Russo の「action-influence が小さい」を厳密確認。
3. **その根本は (a) base が既に公開情報の放銃回避天井(0.93)付近で advantage を使い尽くし、(b) 残差は不完全情報の隠れ手牌＝deployment 不可**（§7.12, §7.14）。

**改善の正道（条件付けの放棄）**: headroom は omniscient→imperfect の **0.068**（小だが高価値ケース集中）。これは条件付けでは届かず、**隠れ情報を教師にした蒸留**でのみアクセス可能:
- **omniscient deal-in/価値モデル → imperfect 生徒へ蒸留**: omniscient で放銃確率/局EVを学び（AUC 0.9997）、imperfect モデルにその予測を soft target として転写。imperfect の公開情報から omniscient 推定を近似する力を、純粋模倣を超えて獲得させる。
- deployment では imperfect 情報のみ使用 → 正当に強くなる（Russo の χ² 保守性も維持）。
- 期待効果は 0.93→上限0.9997 の範囲に bounded だが、−6042点の破滅ケース回避に効く。

## 7.15 ESOC（Entropy-Splitting / Entropy-Gated Conditioning）の実装と決着

「conditioning 無視＝`I(C;A|S)=0`。ならば `I(Z;A|S)` を明示的に強制し、暴走を防ぐため `π_mix=Σ_z q(z|s)π_z ≈ π0`（marginal preservation）と outcome alignment を同時に課す」——理論的に正しく美しい定式化。`scripts/research/esoc_prototype.py` で実装（K 個の latent モード, tilt `π_z∝π0 exp(u_z)`, gate `q(z|s)`, value `V_z(s)`, loss = marginal BC + λ_kl·KL(π_mix‖π0) − λ_mi·I(Z;A|S) + λ_out·Σ_z r_z(Y−V_z)²）。frozen base 特徴上で held-out(by-game) 評価。

**3点同時テスト（make-or-break は (3) の汎化）**:

| K, λ_mi, λ_out | (1) I(Z;A\|S) | (2) KL(π_mix‖π0) | (3) alignment_gain R² |
|---|---|---|---|
| 4, 0.3, 0.5 | 0.219 | 0.042 | **−4e‑5** |
| 2, 0.05, 1.0 | 0.002 | 0.010 | −0.0 |
| 8, 0.1, 1.0 | 0.009 | 0.018 | −1e‑4 |
| 4, 0.0, 1.0 | ~0 | 0.015 | 0.0 |

- **(1)(2) は構成上達成可能**：MI を強制すればモードは大きく分岐（I=0.22, best-mode TV=0.23）し、平均は π0 付近に保てる。
- **(3) は全設定で失敗**：action-informed value が held-out 結果を state-only より良く予測しない（R²_state＝R²_action≈0.07、gain≈0）。モード別平均価値も [−0.172,−0.168,−0.167,−0.172] とほぼ同一＝**結果で分化しない**。

**結論**: ESOC は「条件を無視する解」を数学的に排除できる（MI を立てられる）が、**π0 の打牌エントロピーは「結果的に等価なモード」に分裂するだけ**で、勝ちに相関する戦略モードは潜んでいない。forced-MI を入れても outcome alignment は汎化せず、action-influence の天井は破れない。

**全条件付け手法の統合的決着（§7.5–7.15）**: 観測情報側で行動と結果を結びつける試み——素朴な outcome-conditioning（v1/v2/v3）・密度比（Ratio Head）・強制 MI ＋ marginal preservation（ESOC）——は**すべて同一の天井**に阻まれる。専門家・不完全情報の麻雀打牌では、**観測状態を所与とした行動と（観測可能な）結果の条件付き相互情報が ≈0**。理由は (a) base が既に公開情報の安全打牌天井(放銃AUC 0.93)で advantage を使い尽くし、(b) 残差は不完全情報の隠れ手牌＝deployment 不可（§7.14）。

**唯一未反証で構成的な路＝omniscient→imperfect 蒸留**: 改善信号は「観測側の条件付け」には無く、「隠れ情報を見た教師」にしかない（放銃 AUC 0.93→0.9997 のギャップ）。条件付けを諦め、omniscient で価値/放銃を学び imperfect 生徒へ蒸留するのが、全結果と整合する唯一の改善路。

## 7.16 【重要な訂正】outcome の選び方が悪かった — 即時outcome（放銃）には強い action-influence がある

§7.5–7.15 の「action-influence ≈0／`A⊥Y|H`」は **outcome `Y` の選択ミス**による計測アーティファクトだった。`Y` に半荘着順・局収支バケットという**遠位・運支配（R²_state≈0.07）**の量を使ったため、一手の寄与が分散に埋もれていた。打牌の**直接的・帰属可能・低ノイズな outcome は放銃（即ロン）**であり、これで測り直すと action-influence は大きい（`scripts/research/dealin_action_influence.py`, imperfect, 269,665 打牌）:

| 放銃予測 | AUC |
|---|---|
| 状態のみ P(放銃∣s)（打牌前 hidden@pos-1）| 0.826 |
| 状態+行動 P(放銃∣s,a)（打牌後 hidden@pos）| **0.930** |
| **action-influence（AUC gain）** | **+0.104** |

**訂正後の整合的な描像**:
- 打牌 → **即時outcome（放銃）**: action-influence **大**（AUC +0.10、P(放銃∣s,a)=0.93）。
- 打牌 → **終局着順/局収支**: action-influence ≈0（半荘の運で希釈）。
- ゆえに v2/v3/Ratio Head/ESOC が平坦だったのは「**終局を的にした**」ため。`I(A;Y|S)≈0` は `Y=終局` でのみ真で、`Y=即時` では偽。

**方法論的帰結**: outcome-conditioning／value／ESOC を効かせる正しい的は **即時outcome（放銃リスク・即時EV・手牌前進）**。ここには強い alignment 信号があり、`Y=放銃` で測れば ESOC の (3) も Ratio Head の dCE も汎化するはず（要追試）。

**ただし「改善するか」は別問題（次の決定的測定）**: action-influence が大きくても、専門家が既にそれを exploit していれば改善余地はない。残る問いは「**専門家は即時outcome（放銃EV）に対して最適か、suboptimal か**」。omniscient モデル（放銃AUC 0.9997＝ほぼ真値）で各候補打牌の放銃リスクを採点し、人間の選択牌のリスクが「打てた最も安全な牌」よりどれだけ高いか（＝headroom）を測るのが次の一手。headroom があれば、即時EVの value-tilt（χ²保守的に support 内で安全牌へ寄せる）で正当に強くできる。

## 7.17 解（B）：アドバンテージ順位条件付け — ロールアウト無しで動く改善

探索/ロールアウトは多人数確率ゲームで深さに対し**指数的に分散増大**するため不可。よって**ロールアウト不要の conditioning** が必須。鍵は条件変数を「outcome（低MI・運で希釈・無視される）」から「**アドバンテージ順位（高MI・(s,a)から決定的・無視できない）**」に替えること。実装 `scripts/research/extract_critic_features.py` ＋ `scripts/train_critic_rank_conditioning.py`（323,797 打牌, 3000局）：

1. **短期 critic** `Q(s,a)=P(放銃|s,a)`：状態 hidden ＋ 行動埋め込み → 放銃確率。ロールアウト無しの feedforward 回帰、行動埋め込みで全候補に汎化。held-out **AUC 0.824**（検出可能）。
2. **順位条件付け方策** `π(a|s,rank)=softmax(logπ0 + tilt(hidden,rank))`：support 内行動を critic で順位付け、その順位で条件付け。推論は `rank=最善`。

**結果（held-out, by-game）**:

| 指標 | 値 | 対比 |
|---|---|---|
| critic 放銃 AUC | 0.824 | — |
| **TV(π(·\|best) ‖ π(·\|worst))** | **0.492** | outcome条件付け **0.008** の約60倍 |
| TV(π(·\|best) ‖ π0) | 0.230 | π0 から有意に移動 |
| 期待放銃リスク π0→best | 0.262→**0.231**（−12%）| 改善 |
| best の support 内質量 | **0.975** | χ²保守的 |

**一般化（麻雀特化なし）**: critic のターゲットを**その領域の一般報酬（局スコアの return）**にすれば手作り特徴は不要。放銃は「即時報酬(1-step return)」の特殊例。一般 return critic（`--target return`）でも：

| 指標 | 一般 return critic | 放銃(1-step) 参考 |
|---|---|---|
| critic 検出力 | return R²=0.060 | 放銃 AUC=0.82 |
| TV(best‖worst) | **0.438** | 0.491 |
| 価値改善 best vs π0 | **+0.030** | +0.032 |
| support内質量 | 0.977 | 0.974 |

→ 一般 return でも放銃特殊例と**ほぼ同等の改善**。手法は完全に領域一般。

**結論**: **条件変数を「アドバンテージ順位」にすると conditioning は無視できなくなり（TV 0.44–0.49 ≫ outcomeの0.008）、`rank=最善` で support 内（97.7%）に留まったまま改善（一般returnで+0.030、放銃で-12%）する、ロールアウト無し・領域一般の改善作用素が得られる。** 一連の outcome-conditioning 失敗の根因（低MI条件）を、順位という高MI条件で直接解消。論文の χ²保守的改善（support内 tilt）とも整合。critic 検出力は報酬 horizon に依存（局return R²=0.06 と希釈、即時は AUC0.82）＝「改善を取り出せる horizon は報酬の action-influence で決まる」という一般原理。

**留保 / 次段階**:
1. 改善量は同一 critic 基準（やや楽観）。真の反実仮想放銃 or self-play で検証が必要。
2. **防御（放銃）次元のみ**。critic を **即時EV の多次元**（放銃コスト＋自手前進＋打点；horizon を伸ばさず攻守両立）に拡張し、「最安全＝ベタ降り過剰」を回避すべき。順位条件付けの枠組みは critic 非依存なので、多次元 critic に差し替えるだけで一般化する。
3. 領域一般：本手法＝「ロールアウト無し critic で行動を順位化 → 高MI な順位で条件付け → argmax」は任意ドメインに適用可能。

## 7.18 critic を限界まで強化（領域一般）— capacity ではなくデータが限界

(B) の改善が領域一般かを検証するため、critic を最大強化した：**base LM を LoRA fine-tune**（frozen-head をやめ全表現力）、per-action 価値ヘッド `Q(s,·)` ＋ 状態価値ヘッド `V(s)`、**ターゲットは一般 return（局スコア）のみ**（放銃/ron/手牌など麻雀特化ラベルは一切なし）。8000局・3エポック。`scripts/train_critic.py`。

決定的指標：`gain = R²_Q(状態+行動) − R²_V(状態のみ)` = 一手が一般 return 予測に足す情報＝検出可能な action-advantage。

| epoch | R²_V(状態) | R²_Q(状態+行動) | gain |
|---|---|---|---|
| 1 | 0.106 | 0.105 | **−0.0014** |
| 2 | 0.108 | 0.107 | −0.0014 |
| 3 | 0.105 | 0.103 | −0.0014 |

- **状態価値は強化された**：R²_V 0.06(frozen) → **0.11**（fine-tune で約2倍）。capacity は確かに効く。
- **だが action-advantage は ≈0**（gain −0.0014、安定）。per-action ヘッドは全行動に V を出すよう収束＝行動は一般 return 予測に何も足さない。

**結論**: **capacity はボトルネックではない。一般 return に対する per-action advantage は critic をどれだけ強化しても ≈0**＝データ固有。Russo の action-influence ≈0 を最大容量で確認。

**§7.17 の (B) 改善（放銃 -12%）は領域知識依存だった**：放銃は「即時・帰属可能」outcome なので action-influence が立つ（AUC 0.82）が、これは「自分の打牌直後のロン＝その打牌に帰属」という麻雀の構造知識を使っている。希釈された一般 return にはこの帰属性が無く、一般 critic では advantage 0。

**原理的トレードオフ（全研究の最終形）**: 検出可能な per-action advantage を offline・無探索で得るには次のいずれかが必要——
- **(a) 領域知識**：即時・帰属可能な outcome を定義（放銃など）。← 麻雀特化。
- **(b) 特権情報**：omniscient critic（放銃 AUC 0.9997）。← 追加情報。
- **(c) ロールアウト/探索**：多人数確率ゲームで指数的希釈。← 不可。

**一般 × 無探索 × オフライン × 希釈outcome の4条件同時では、action-advantage は構造的に ≈0**。これが、本研究を貫く「outcome-conditioning が効かない」現象の、capacity を排除した最終的な根拠。改善には上記(a)(b)(c)のいずれかの構造を必ず導入する必要がある。

## 7.19 critic を imperfect 情報の上限まで強化（option 1：行動を model に通す）

「即時・帰属可能報酬」原則の下、critic を限界まで強化。鍵は容量ではなく **(i) 候補行動を model に通した hidden@pos から価値を読む（per-action head でなく）＋ (ii) クリーンな二値の的（即時・帰属可能な悪事象＝deal-in）**。`scripts/train_critic_processed.py`（LoRA fine-tune、8000局、KVキャッシュ反実仮想評価）。

| critic 構成 | deal-in AUC(held-out) |
|---|---|
| per-action head @pos-1（状態のみ＋行動埋め込み）| 0.82 |
| action-processed × signed報酬の**回帰** | 0.74（疎target で劣化）|
| **action-processed × 二値 deal-in 分類**（本節）| **0.936** |
| frozen hidden@pos 二値プローブ（既測の上限目安）| 0.93 |
| omniscient（特権情報, 参考上限）| 0.9997 |

→ **deal-in AUC 0.936**＝imperfect 情報の上限に到達。容量(LoRA)＋行動処理＋クリーン二値target の三点が効いた。回帰(0.74)・per-action head(0.82) を大きく上回る。

**反実仮想順位評価（4212状態, KVキャッシュで各候補を通す）**：
- 最安全候補 vs π0 の TV = **0.578**、best in-support = **1.0**（χ²保守）、**deal-in リスク低減 = −0.087**（最安全 support 内牌を選ぶと放銃確率を約8.7pt 低減）。

**到達点**: ロールアウト無し・imperfect 情報・上限級（AUC 0.936）の critic が、support 内に留まったまま大きな防御改善（−0.087）を駆動する。これで「critic を限界まで強化」は達成（情報ceiling まで到達、これ以上は特権情報蒸留が必要）。

**正直な留保**:
1. リスク低減は同一 critic 基準（最安全を選ぶので自明に低い）。AUC 0.936 で held-out 汎化は強いが、真の反実仮想 deal-in 検証にはエンジン/self-play が要る。
2. これは**防御（deal-in）単独**の critic。最安全のみだと過度のベタ降り（TV 0.578 と π0 から大きく乖離＝攻撃EV損）。完全な方策には**攻撃次元との多次元統合**（即時の自手前進/打点を同じ即時・帰属可能枠で足す）が必要。順位条件付けの枠組みは critic 非依存なので、多次元 critic に差し替えるだけ。

## 7.20 Controllable Consequence Conditioning (CCC) — 成功（自動発見した収支整合・帰属可能 proxy）

**動機**: deal-in は「行動直後に強く反応する（高 action-influence）」が「目的関数として不適切（防御＝loss回避のみ、収支/着順と部分的にしか整合しない）」。**行動直後に強く反応し、かつ放銃是非より収支・着順と整合する proxy を、deal-in/安全度/シャンテンを手で設計せずに自動発見する**のが CCC。一般原則「即時・帰属可能な帰結を critic の的にする」の下、領域非依存の手続き。

**定式化**: 帰結表現 φ(s,a)＝**行動を model に通した hidden**（hs[pos]、deal-in を線形に読める＝AUC 0.936 の表現）。制御可能帰結 g(s,a)=φ(s,a)−E_{a'~π0}[φ(s,a')]（E[·|s] は ridge state→φ で推定。a⁺~π0 なので状態条件平均＝π0平均）。proxy c_u=u·g。目的 J(u)=E_s Var_{a~π0}(u·g) × Corr(u·g, Y−V(s))²。

**2つの実装ミスの修正（v1 は align 0.036 < deal-in で失敗）**:
1. **帰結表現**: v1 は z_next＝「次の意思決定の事前状態」を教師なし遷移モデルで予測 → deal-in を構造的に喪失（放銃すると局が終わり「次の意思決定」は無関係な新局の先頭）。v2 は φ=hs[pos]（行動処理済み hidden、deal-in が線形可読）。⇒ deal-in の中心化読み出しが g の張る空間に**含まれる** → 探索空間が deal-in を内包 → 最適は deal-in 以上。
2. **最適化**: g は状態ごとに中心化（E_{a~π0}[g|s]=0）。総分散の法則より influence(u)=Var_{s,a~π0}(u·g)=取った行動標本上の Var（反実仮想不要）。さらに条件付けは proxy の閾値/順位で行う＝スケール不変 ⇒ 改善関連量は**相関（alignment）**。最大相関の線形読み出し＝ridge 回帰 Y~~g。v1 の ridge(Σ⁻¹b) は高分散方向を**抑制**しており逆。

**発見結果（held-out, game-split, 323,797 打牌決定, 3000局）** `scripts/research/ccc_discover_v2.py`:

| proxy | 収支残差 Y~ との alignment(相関) |
|---|---|
| deal-in（放銃是非, realized ron ラベル使用）| 0.132 |
| **CCC c\*（自動発見, decision-time, φ のみ）** | **0.121** |
| **c\* + deal-in 併用** | **0.173** |
| **c\* の deal-in を超える寄与（partial）** | **+0.111** |
| deal-in の c\* を超える寄与 | −0.123 |

- **c\* と deal-in の重なりは −0.076（ほぼ直交）**。両者は**異なる**収支関連の制御可能信号を担う。c\* は deal-in の上に **+0.111** の alignment を足し、併用で 0.173（deal-in 単独比 **+31%**）。⇒ **CCC は防御専用の deal-in が取りこぼす「攻撃軸」（自手の打点/前進）を自動発見した**＝まさに「放銃是非より収支と整合する proxy」。
- c\* 単独 0.121 ≈ deal-in 0.132。0.011 の差は deal-in の**予測不能な運成分**（realized ron は φ に無い）。decision-time の制御可能 alignment の天井に c\* が到達。
- 帰結を中心化済み（g）＝**100% 局面内（行動駆動）**。状態間分散ゼロ ⇒ action-attributable が保証され、influence×alignment² の influence 項は規格化後どの中心化 proxy も最大 → J∝alignment² → 最大化＝c\*。「J を最大化すると covariance 方向（dir1, Var 8.56, align 0.05）」は絶対スケールを最大化する見かけ上の罠で、規格化された改善量は alignment。

**二値化と符号（steps 6-7, 完成）**: c\* を中央値で二値化。good 側＝c\*≥thr（meanY~=+0.112 vs −0.089、**収支ギャップ +0.20**）。決定の 50% が good 側 → 条件付けで動かす余地大。good に条件付け＝収支の高い行動側へ誘導。

**条件付けの非無視性（原初の失敗＝OCは無視される TV 0.008 を解消）**:
- 状態のみ tilt head `ccc_conditioning.py`: swing TV(good||bad)=**0.088 ≈ 11×** terminal-OC の 0.008、in-support 0.988（χ²安全）。状態のみでは候補別 c\* が見えず動きは控えめ。
- **反実仮想 c\* 順位条件付け** `ccc_rank_conditioning.py`（各 in-support 候補を model に通して c\*(s,a) を直接採点、best=good に条件付け、1528状態）: **TV(best||π0)=0.612**、**best in-support=1.0**、平均 c\* gain(best vs π0)=+0.043。⇒ **deal-in critic の TV 0.578 を上回り**、terminal-OC の 0.008 の **約76倍**。χ²信頼領域内（support 100%）で強く動く＝非無視かつ収支整合の条件信号。

**到達点**: CCC は、手で deal-in を設計せず、**行動直後に強く反応し（action-attributable, 非無視 TV≫0.008）かつ収支と整合する（alignment 0.121、deal-in を超える +0.111 の攻撃軸）制御可能帰結 proxy を自動発見**した。これは原初の「OC が無視される／放銃是非は防御専用」を両方解決する。

**正直な留保**: (1) alignment/収支ギャップは offline 残差基準（真の方策改善はエンジン/self-play 要）。(2) c\* 単独の raw alignment は deal-in を僅かに下回る（0.121 vs 0.132）が、その差は**運成分**で行動不能。decision-time で deal-in に匹敵し、かつ deal-in 直交の攻撃軸を足せる点が本質的優位。(3) c\* は線形読み出し＝φ が deal-in/打点を線形に内包する前提（AUC 0.936 で妥当）。

## 7.21 CCC を全意思決定点に拡張（discard だけでない）

§7.20 の CCC は打牌専用だった。CCC の核（φ(s,a)=hs[pos]、g=φ−E[φ|s]、c\* の順位条件付け）は**意思決定点に非依存**なので、目線プレイヤーの**全意思決定点**に拡張した:
- **discard**（打牌）/ **self**（自摸時：ツモ和了・立直・暗槓・加槓・抜き）/ **react**（他家打牌への反応：ロン・ポン・チー・カン・自発パス）/ **chi_pos**（チー消費面子）/ **red**（赤5使用・不使用）/ **kan_tile**（暗槓・加槓・抜きの対象牌）。

実装: `src/gpt2/viewer_decisions.py`（`iter_viewer_decisions` は `is_viewer_action_token` と**完全パリティ**＝400局0不一致で検証、各点の型と候補集合を返す）+ `extract_ccc_features_all.py`（全点で state=hs[pos-1], φ=hs[pos] 抽出、434,000 決定/3000局）+ `ccc_discover_all.py` + `ccc_rank_conditioning_all.py`（型別候補列挙で反実仮想ランキング）。即時帰結ラベルは型依存（放銃/和了/打点…）だが **CCC は g=φ−E[φ|s] から自動発見するので型横断で同一の c\* 発見器**を使う。

**決定数（3000局）**: discard 323,797 / react 72,478 / self 31,679 / chi_pos 3,932 / red 1,447 / kan_tile 667。

**発見（held-out, 単一の universal c\* を全点に適用）** `ccc_discover_all.py`、overall alignment=**0.120**:

→ **1個の universal c\* が全意思決定点で収支と整合**（0.06–0.22）。型別に fit すればさらに上（self 0.150, react 0.137 等）。**稀だが高分散なサブ選択（赤5使用 align 0.215/gap 0.40、カン対象 gap 0.57）ほど収支ギャップが大きい**＝1手で EV が振れる勝負所で proxy がよく効く。

## 7.22 CCC への3つの指摘と修正（目的関数・多軸・条件付けの本質）

オーナーから3点の本質的指摘。すべて妥当として対応:

**② 目的関数の修正（最重要）— Y は局収支でなく最終着順の段位ポイント.** v2/v3 の Y は局スコア差バケット（`BUCKET_VALUE`）だったが、これは「その局でチップを稼いだか」であって目的でない。東1で大量リード時の+8000 は段位pt ≈0、オーラスで3着→2着を決める+2000 は決定的——**局収支は真の目的の単調関数ですらない**。正しい目的は `Y = uma(最終着順)`（段位pt）、正しい近位target は**着順エクイティの変化**（faithful reduction, §6）。`scripts/research/extract_placement_target.py`（final_rank から着順→段位pt、TENBO から局境界スコア）+ `ccc_discover_targets.py` で3目的を比較（held-out, 434k決定）:

| 目的 Y | c\* alignment(overall) | discard | self | react | state R² |
|---|---|---|---|---|---|
| 局収支バケット（旧・誤）| 0.120 | 0.126 | 0.125 | 0.110 | 0.097 |
| **着順段位pt（terminal, 正）**| **0.115** | **0.144** | 0.082 | 0.065 | 0.097 |
| 着順エクイティ変化（粗35bin）| 0.085 | 0.093 | 0.108 | 0.063 | 0.048 |

→ **CCC は誤った局収支目的に依存していない**。着順段位ptで refit しても c\* は alignment 0.115（支配的な打牌では 0.144 と**むしろ向上**）。φ（行動処理済み hidden）は最終着順を十分エンコードしている。self/react は低下（0.082/0.065）——局収支が副露/立直を即時局結果で**過大評価**していた分が剥がれた正直な結果。粗い経験的エクイティ表(0.085)は劣るが、**正しいエクイティ関数は35bin表でなく hidden 由来の V(s)**＝`place` 目的の baseline（Y~=段位pt−V(s)）が既にそれ。よって**採用目的＝着順段位pt＋neural equity baseline**。手作り局収支バケットは廃止。

**① 単一軸→多軸.** `c*=w·g` の単一スカラーは守備/攻撃/テンポを潰す。着順目的下で PLS 分解（`ccc_multiaxis.py`）すると軸が分離:
- 軸2: align_place 0.060 / corr_round 0.050 / **influence 最大 4.37** ＝テンポ・点棒軸。
- 軸3: align_place 0.036 / **corr_round −0.014** ＝**純・着順管理軸**（点棒に中立〜負だが着順を上げる＝リード時のベタ降り）。**局収支目的では見えない/罰される軸**——②の重要性を具体的に裏付ける。
スカラー c\*(0.115) は最適1次元結合を既に捉える。多軸の価値は**独立ステアリング**（「着順を守る」vs「打点を押す」を別々に条件付け）＝③の条件付け target。

**③ conditioning でなく強制 reranking — 軽量版を実装（`ccc_conditioning_v2.py`）.** 現状 `argmax c*` は外部リランカで、TV(best‖π0)=0.6 は「候補~3個での one-hot argmax」を主に反映。真の条件付けは `P(a|s, t)`（t=望む帰結ベクトル）。frozen LM＋**連続多軸 c\*-target tilt** head を学習（着順目的, K=3, π=softmax(logπ0+tilt(state,t)), CE on a+ with t=標準化 c\*(a+)）。**held-out 結果**:

| 指標 | 値 | 読み |
|---|---|---|
| dNLL(true − shuffled target) | **−0.63** | target に強く条件付く（ただし候補~3個なので**一部は action-identity leakage**で過大）|
| cstar_steering_corr | **0.285** | good vs bad で高 c\* 行動を実際に upweight＝**汎化する真のステアリング（純 leakage でない）** |
| swing TV(good‖bad) / TV(good‖π0) | 0.68 / **0.35** | argmax の one-hot(0.61) と違い**較正された分散シフト** |
| good in-support | **0.91** | χ²信頼領域内 |
| return_steering_corr（対着順 Y~）| **0.0015** | **offline では結論不能**（着順は1局1ノイズbit/局内共有、c\* 自身の着順 alignment も 0.144）|

→ **③は「genuine conditioning（較正・操作可能・support内、c\* で汎化ステアリング corr 0.285）」を達成し、forced rerank を置換**。ただし正直な留保2点: (a) 打牌は in-support 候補が~3個と少なく、連続 target が行動を部分的に同定する **leakage** で dNLL が過大（候補の多い決定点では緩和の見込み）; (b) **真の着順改善は offline 指標では判定不能**（着順 Y~ が過疎ノイズ）→ self-play 必須（オーナー判断で保留中）。argmax rerank は「条件付け」ではないが support 内 c\*-best を保証する点で相補的。

## 7.23 実対戦評価（Majiang エンジン）— CCC は実戦で着順を悪化させる

オフライン指標が結論不能だったため、kobalab 電脳麻将エンジン（`MitsuhiroTaniguchi/Majiang`）で実対戦評価。SEAT0=MahjongLM、SEAT1-3=エンジン内蔵AI、同一 seed の四麻で **base（argmax π0）vs CCC（argmax c\*）を paired 比較**。CCC は base 上の純粋なリランカ（行動処理済み hidden の c\* で in-support 候補を採点、最良を選ぶ。conditioning token 不要）。実装: `Majiang/mahjonglm-ccc-server.py`（HTTP /generate に CCC mode、prefix KV キャッシュ＋候補バッチ単発ステップで高速化、正確性検証 logit差<3e-5）、`scripts/research/run_match_ab.py`（共有GPUサーバー1台＋12並列ワーカー、240局を約21分）。

**結果（held-out, 120局 paired, t検定）**:

| 指標 | base (argmax π0) | CCC (argmax c\*) | paired Δ |
|---|---|---|---|
| 平均着順 | **2.417** | 2.933 | +0.517（t=3.86, **悪化**）|
| 平均ポイント | **+1.73** | −14.96 | −16.69（t=3.90, **悪化**）|
| 着順 better/worse/same | — | 27 / **62** / 31 | |
| ポイント >/</= | — | 38 / **82** / 0 | |

→ **CCC の argmax リランクは実対戦で base より有意に弱い（着順 +0.52, t≈3.9）**。オフラインの c\* 着順 alignment（0.12）は実戦改善に**転移しなかった**。

**診断（control 比較, 同一 base・同一 seed, N=120 each）**:

| 方策 | 平均着順 | 平均ポイント | vs base d_rank (t) |
|---|---|---|---|
| **base (argmax π0)** | **2.425** | **+1.13** | — |
| ccc (argmax c\*) | 2.925 | −15.06 | +0.500 (t=3.75) |
| worst (argmin c\*) | 3.000 | −17.46 | +0.575 (t=4.35) |
| random (in-support 一様) | 3.025 | −19.20 | +0.600 (t=4.83) |

順序: **base ≪ ccc < worst ≈ random**。2つの明確な結論:
1. **π0-argmax からのいかなる in-support 逸脱も約 −0.5 着順の損**（random も worst も ccc も全て t>3.7 で悪化）。10M base の argmax は既に良較正で、π0≥0.02 の代替手は平均的に劣る手。
2. **c\* には実在するが微小な正方向の信号**: ccc（argmax c\*, 2.925）は3逸脱中で最良＝random(3.025)・worst(3.000) より良い。高 c\* > random > 低 c\* で c\* は弱く着順整合。しかし random に対する優位（約0.1着順）は、π0モードを離れる代償（約0.5）を覆すには **約5倍足りない**。

**含意（研究全体の capstone）**: これは Russo の核心「強い behavior policy では in-support の action-influence が構造的に小さい」が**実戦で顕在化**したもの。模倣方策が強いほど support 内の改善余地は微小で、弱い proxy の真の信号は「較正された行動から逸脱する代償」に飲まれる。**オフラインの "成功"（§7.20–7.22 の alignment 0.12・TV 0.6）は実戦の強さを意味しない**——オーナーの「実対戦で評価すべき/offline指標は信用するな」が実証された。CCC を実戦で効かせるには (1) 対戦分布での critic 学習（人間データのみでは OOD）、(2) c\* の信号を桁で強くする、(3) そもそも π0-argmax を超える headroom が小さい前提を受け入れる、のいずれかが要る。現状の rollout-free・人間データ critic では純益は出ない。

## 7.24 CCC 実戦失敗の根本原因究明（解剖）

オーナーの指摘（「オフライン成功がオンラインで崩れるのは不自然、バグ/認識相違で戦略が破壊されている」「運用が間違っている」）を受け、徹底解剖。**2つの実装バグ＋1つの本質的アルゴリズム欠陥**を特定。

**バグ① 特徴抽出に `<bos>` 欠落.** 事前学習は `<bos>`/`<eos>` を後付けし、ライブ player も `<bos>` を前置するが、`extract_ccc_features_all.py` は生 `input_ids`（bos 無し）で hidden を抽出していた → c\* head を**学習分布外の hidden で fit**。修正: `[<bos>]+ids` で再抽出（state=hs[pos], φ=hs[pos+1]）、placement 目的で head 再 fit。

**バグ② VRAM 24GB 異常 = HTTPスレッドで grad 有効.** `torch.set_grad_enabled(False)` は**スレッドローカル**で、`ThreadingHTTPServer` の各リクエストは新スレッド→grad ON→autograd グラフ蓄積で 24GB。修正: 各推論関数に `@torch.no_grad()`。（さらに一時的 mem-cap 0.25 + grad-ON が CUDA OOM→サーバ500→player フォールバックを誘発し base が rank3.83 に見えた人為現象も解消。修正後 base=rank2.20/+8.6pt, VRAM 287MiB。）

**しかし両バグ修正後も CCC は base に負ける（rank2.20→3.05）**。保守的条件付け（`argmax(logπ0+β·z(c*))`, β掃引）でも **β に単調に悪化**（β1: +0.40, β3: +0.70 悪化）。argmax が過激なのではなく、c\* 方向へ少しでも動かすと負ける。

**根本原因（実局面の解剖 `dissect_ccc_failure.py` / live dump）:**
- c\* は held-out の**取った行動**上では着順と単調・状態直交（Corr 0.125, decile −15.5→+16.9, R²(c\*~state)=0）＝良い予測子に見える。
- **だが c\* = w·g, g = φ(s,a) − E_{a'~π0}[φ(s,a')]（方策平均からの帰結偏差）。典型行動（高π0）は φ≈平均→g≈0→c\*≈0、非典型行動（π0≈0）は φ が平均から大きく外れ→|g| 大→|c\*| 大。** よって **c\* は方策が最も嫌う手で最大**になる。
- ライブ実局面の dump で実証: 手牌 `m2m4m5m6m7 s8s9 z2z3z4 z6z6z6` で **c\* 最大手は z6（完成刻子を割る）/ m6,m7（456m7 の順子を割る）/ m2（ツモ切り）= すべて π0≈0 の破滅手**。π0-argmax は正しく s9/z4 等。
- ∴ argmax/tilt-c\* は構造的に **OOD（低π0）の悪手**を選ぶ。offline alignment 0.125 は「平均近傍の取った行動」上だけの観測的相関で、**全候補上の argmax には転移しない**（g は非典型行動で最大→選択が OOD に支配される）。in-support 閾値 0.02 は部分的にしか守らず、exp-tilt でも β とともに非典型側へ漏れて単調悪化。

**結論**: CCC 失敗は bos/grad バグ（修正済）ではなく、**「方策平均からの偏差 g を行動の選択/条件付けスコアに使う」構成自体が OOD 行動選択バイアスを持つ**こと。観測的整合（取った行動上 0.125）は介入（全候補 argmax）に転移しない。正しい運用は**選択を方策の高確率サポート内に厳しく制限**（tight χ² 信頼領域）するか、**条件付き生成方策 P(a|s,target) を学習**して in-distribution に生成すること（argmax/tilt で π0≈0 候補に到達させない）。inference-time の deviation-score reranking という運用が誤りだった。

## 8. χ² 幾何が麻雀 AI 設計に与える示唆

- **崩れにくさ**: χ² 信頼領域は「人間が稀にしか打たない奇手」へ確率を移すことを強く罰する。OC 麻雀 AI は**奇抜だが弱い手**に走りにくく、人間上位分布の**支持内で最善手に集中**する保守的改善になる。実戦的にはこれは望ましい性質（過学習的ギャンブルを避ける）。
- **過保守の罠**: 同じ性質ゆえ、action‑influence が小さい平坦な局面では OC はベースとほぼ同じ手を打つ。ここで「強くなった感」が出ないのは**バグではなく理論通りの失敗様式**（Prop 4.3 の解釈）。改善は action‑influence が大きい勝負所に集中する。
- **温度パラメタ不要**: 論文 §7.2 の指摘通り、success conditioning は `exp(βQ)` 型（DPO/AWR/SAC 等の KL 幾何）と違い `β` を持たず、信頼半径がデータから自動決定される。本リポジトリの DPO パイプライン（`docs/view_imperfect_dpo.md`）は KL 幾何（reverse 寄り）であり、**OC（χ² 幾何）と DPO（KL 幾何）は別物**。両者の幾何差（Fig 1）を踏まえ、用途で使い分け／比較するのが筋。

## 9. 既知の注意点・落とし穴

1. **合法手マスク**: 方策分布を測る際は、語彙 828 全体ではなく**その局面の合法行動**（例: 打牌なら手牌中の牌種、reaction なら提示された take/pass）に制限して再正規化しないと、χ²/KL が無意味になる。決定点の文法は `tests/test_engine_decision_tokens.py` に詳しい。
2. **全席着順ベクトル条件付け**: 「viewer=トップ」は単独指定できず、他 3 席の順位も与える必要がある。実験では他席順位を周辺化（複数割当を平均）するか、代表割当を固定するかを明示すること。
3. **view 交絡**: §1.2 の通り、OC アダプタが「imperfect 適応」と「outcome 条件付け」を同時学習している可能性。**対照**として「着順プレフィックスを与えない／ランダム着順を与えた OC」を作ると純粋な条件付け効果を切り分けられる。
4. **学習量**: OC は 0.11 epoch・LoRA r=64 と軽量。P3 で「条件をほぼ無視」が出た場合、過保守（理論的失敗）か単なる学習不足かの切り分けに、学習量を増やした追試が要る。
5. **`M>1`（§3, §5）**: Prop 5.1 の罰則ゼロは局所トークン遷移にのみ妥当。半荘結果に対する分布シフト罰則は残るため、オフライン eval loss の小ささが即「強い」を意味しない。最終判断は P5 の self‑play を要する。
